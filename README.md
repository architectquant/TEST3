### ⚡ Keep your GitHub forks synchronized effortlessly.

A Python command-line tool that automatically discovers GitHub forks owned by an authenticated account and requests upstream synchronization through the official GitHub API.

Designed to make fork management easier, faster and more convenient. 🧩⚡

> 💜 Simple workflow. Secure authentication. Reliable synchronization. And a tiny bit of magic ✨.





---


## ✨ Requirements

Before getting started, make sure you have:

- 🐍 **Python 3.11+**
- 🔑 **GitHub Personal Access Token** with access to the repositories being synchronized and permission to update them.
- 🔐 **Operating-system keyring backend** required for saved accounts.

No cape required. 🦸



---

## 📦 Installation

### 1. Clone the repository

```bash
git clone https://github.com/Dreamerol/DREAMEROL-SYNC.git
cd DREAMEROL-SYNC
```

### 2. Create a virtual environment

```bash
python -m venv .venv
```

### 3. Activate the environment

🐧 macOS / Linux

```bash
source .venv/bin/activate
```

🪟 Windows PowerShell

```powershell
.venv\Scripts\Activate.ps1
```

### 4. Install dependencies

```bash
pip install -r requirements.txt
```

## 🔐 GitHub Authentication and Saved Accounts

Create a `.env` file in the project root and configure your GitHub token.

```dotenv
GITHUB_TOKEN=your_github_token_here
```

You can also use the built-in saved account manager described below.

> ⚠️ Security Notice
>
> Keep your GitHub tokens private.
> Never share your credentials or commit your `.env` file.
> The `.env` file is ignored by Git.

### ➕ Add an account

```bash
python main.py --add-account
```

Tokens are entered without echo and securely stored using your operating system's keyring.

### 🔑 Sign in through the Auth Broker

```bash
python main.py --login
```

Set the Broker URL with `--broker-url` or the `BROKER_URL` environment variable:

```bash
python main.py --login --broker-url https://broker.example.com
```

The CLI keeps the polling secret in memory, displays the Broker-generated GitHub authorization URL, stores the returned credential in the system keyring, and acknowledges the credential only after storage succeeds. If keyring storage fails, the CLI does not acknowledge the credential and offers a safe retry while the transaction remains valid.

### 🚀 Deploy the Auth Broker

The Broker is the FastAPI application in `auth_broker/`. Configure the GitHub App client and callback URL:

| Variable | Required | Description |
|:---|:---|:---|
| `GITHUB_APP_CLIENT_ID` | Yes | GitHub App client ID. |
| `GITHUB_APP_CLIENT_SECRET` | Yes | GitHub App client secret. |
| `BROKER_CALLBACK_URL` | Yes | Fixed callback URL. Local default: `http://127.0.0.1:8000/auth/callback`; remote deployments must use HTTPS. |
| `BROKER_REQUEST_TIMEOUT` | No | GitHub token-exchange timeout in seconds. Default: `30`. |

Run the Broker with:

```bash
uvicorn auth_broker.app:create_app --factory --host 127.0.0.1 --port 8000
```

For a remote deployment behind an HTTPS reverse proxy, bind the proxy-facing interface explicitly and configure HTTPS plus the proxy address.

When started through the factory without an explicit configuration, the Broker loads variables from `.env` in the working directory. Passing a `BrokerConfig` to `create_app()` bypasses environment loading.

Rate limits are enabled by default and stored in memory per process:

| Variable | Default |
|:---|:---|
| `BROKER_RATE_LIMIT_ENABLED` | `true` |
| `BROKER_RATE_LIMIT_WINDOW_SECONDS` | `60` |
| `BROKER_RATE_LIMIT_START_PER_IP` | `60` |
| `BROKER_RATE_LIMIT_CALLBACK_PER_IP` | `120` |
| `BROKER_RATE_LIMIT_POLL_PER_IP` | `240` |
| `BROKER_RATE_LIMIT_POLL_PER_TRANSACTION` | `60` |
| `BROKER_RATE_LIMIT_ACK_PER_IP` | `60` |
| `BROKER_RATE_LIMIT_ACK_PER_TRANSACTION` | `10` |
| `BROKER_RATE_LIMIT_FAILURES_PER_IP` | `30` |

Blocked requests receive `429 Too Many Requests` with a `Retry-After` header; the browser callback returns an HTML `429` page. Invalid polling secrets and callback state/code values count toward `BROKER_RATE_LIMIT_FAILURES_PER_IP`; poll and ACK also have per-transaction limits.

Set `BROKER_TRUSTED_PROXIES` to a comma-separated list of reverse-proxy IPs or CIDRs that are allowed to supply `X-Forwarded-For`. Leave it empty when clients connect directly. When configured, the Broker uses the rightmost untrusted forwarded address for per-IP limits.

Rate-limit counters are local to each process and are not shared between workers. Adjust the limits for shared NAT environments, or deploy a shared limiter if strict global limits are required.

### 📋 List saved accounts

```bash
python main.py --list-accounts
```

### 🔍 Preview account repositories

```bash
python main.py --dry-run --account octocat
```

### ⚡ Synchronize an account

```bash
python main.py --account octocat
```

### 💡 Account selection

- Multiple saved accounts require `--account USERNAME`.
- If `GITHUB_TOKEN` is configured, it is used unless `--account` is explicitly supplied.
- Saved-account commands require a functioning operating-system keyring.

## 🧭 CLI Usage and Synchronization Modes

DREAMEROL SYNC provides two synchronization modes:

- 🔍 **Dry Run** — preview selected repositories without making changes.
- ⚡ **Live Sync** — request actual upstream synchronization through GitHub.

### 🔍 Preview synchronization

Preview all discovered forks without changing repositories or requiring confirmation.

```bash
python main.py --dry-run
```

Preview a selected fork:

```bash
python main.py --dry-run --repo octocat/project-fork
```

Select multiple forks by repeating `--repo`:

```bash
python main.py --dry-run --repo octocat/project-fork --repo octocat/another-fork
```

### ⚡ Live synchronization

To perform an actual synchronization, simply omit `--dry-run`.

```bash
python main.py
```

Or synchronize a specific repository:

```bash
python main.py --repo octocat/project-fork
```

## 🌐 Web Dashboard

The repository also includes a FastAPI-backed browser dashboard in `api/`, with static assets in `DASHBOARD/` and welcome-page assets in `web/`. It supports Auth Broker sign-in.

Start the Broker and the dashboard on separate local ports:

```bash
uvicorn auth_broker.app:create_app --factory --host 127.0.0.1 --port 8000
uvicorn api.app:app --host 127.0.0.1 --port 8001
```

The dashboard reads `BROKER_URL` from `.env` (default: `http://127.0.0.1:8000`). Open `http://127.0.0.1:8001` and click **Sign in with GitHub**.

The dashboard creates a server-side session, opens the Broker-generated GitHub authorization URL, and polls `/api/auth/status`. The API validates the returned credential with GitHub, keeps it in server memory, and acknowledges the Broker only after successful validation. The browser receives only an `HttpOnly`, `SameSite=Lax` session cookie; the GitHub token is never returned to browser JavaScript and is not read from the saved-account keyring.

All `/api/` responses use `Cache-Control: no-store`, and state-changing endpoints accept only `POST`. If the dashboard runs behind an HTTPS reverse proxy or tunnel, start Uvicorn with `--proxy-headers` and the proxy address in `--forwarded-allow-ips` so the session cookie is marked `Secure`.

The welcome page does not provide a manual personal-access-token form; browser users must sign in through the Auth Broker.

The dashboard shows fork-only counters — `TOTAL FORKS`, `UP TO DATE`, `TO BE SYNCED` and `UNSYNCABLE` — and synchronizes only forks shown as `behind`, after an explicit `SYNC` confirmation.

> Web sessions and credentials are stored in process memory for 10 minutes, are lost when the API restarts, and are not shared between multiple workers. Run a single API worker, or add shared session storage before scaling horizontally.

### 🧪 One-command local smoke test (Windows)

```powershell
.\scripts\start-smoke.ps1 -Watchdog
.\scripts\stop-smoke.ps1
```

`start-smoke.ps1` starts the Broker on `127.0.0.1:8000` and the dashboard on `127.0.0.1:8001`, waits for Broker `/healthz`, and verifies the dashboard. It does not start a tunnel or rewrite `BROKER_CALLBACK_URL`. Use `-Force` to restart an existing run and `-DryRun` to check prerequisites only.

With `-Watchdog`, `start-smoke.ps1` also starts `watch-smoke.ps1`. The watchdog checks `/healthz` every 5 seconds and restarts the Broker or dashboard on its local port if needed. Run a single check with `.\scripts\watch-smoke.ps1 -Once`. `stop-smoke.ps1` stops the watchdog first, then the dashboard and Broker.

Set `GITHUB_APP_CLIENT_ID` and `GITHUB_APP_CLIENT_SECRET` in `.env` before the real login.

#### GitHub App installation requirements

1. **Callback URL:** set once to `http://127.0.0.1:8000/auth/callback` (local default). Disable wildcard callback matching.
2. **Token expiration:** user-to-server token expiration must be opted out for the approved OAuth flow.
3. **Repository permissions:** grant **Contents: Read and write** and **Metadata: Read-only** required for preview and `merge-upstream` sync.
4. **Installation/account access:** install the app on the account/organization that owns the forks and grant access to the repositories, all or selected, you intend to sync. The signed-in user must have write access to each fork; diverged forks are never auto-synced.
5. **Network:** leave `BROKER_TRUSTED_PROXIES` empty for direct loopback access; configure it only behind a trusted reverse proxy.

#### When re-authorization is required

- Re-authorize and sign in again after changing the app's permissions or requested access.
- Re-authorize after installing the app on another account/organization or changing repository access, for example adding forks or switching from selected repositories to include the target fork.
- If sync returns `HTTP 403` / `Resource not accessible by integration`, verify installation and **Contents: Read and write** access for that specific fork/profile, then re-authorize and retry on one safe `behind` repository.

## 📊 Synchronization Results and Safety

Each repository receives a status describing the synchronization result.

| Status | Description |
|:---|:---|
| ✅ `synced` | GitHub accepted the upstream synchronization request. |
| 🟢 `up-to-date` | Fork and upstream already match. |
| 🔵 `behind` | Preview found upstream commits that can be synchronized. |
| 🟡 `ahead` | Fork has local commits and is not safe to merge automatically. |
| 🟠 `diverged` | Fork and upstream have both changed; automatic sync is refused. |
| ⚠️ `conflict` | GitHub reported a synchronization conflict (HTTP 409). |
| ❌ `error` | Repository data was invalid or an API request failed. |

> 📌 Exit status
>
> The CLI exits with a non-zero status if any repository reports `error` or `conflict`.

Live synchronization can update a fork's default branch. For this reason, the application requires explicit confirmation before proceeding. The tool displays the selected repositories and asks you to type:

```text
SYNC
```

Only the exact confirmation `SYNC` allows the operation to continue. Any other input cancels the run. There is intentionally no confirmation-bypass flag.

Repository filters match the exact `owner/repository` name among forks belonging to the selected account. A repository that does not match is reported as an error rather than silently ignored.

## 📌 Dependency Reproducibility

`requirements.txt` pins the direct dependencies used by the CLI, Broker, API and tests. The minimum supported version is Python 3.11, required by `httpx2==2.16.0`; CI validates on Python 3.11 and 3.12.

It is not a complete transitive lockfile.

For byte-for-byte reproducible environments, generate and commit a platform-aware lockfile, for example using `pip-compile --generate-hashes`, after resolving dependencies for the supported Python and platform matrix.
